## 1. What this repo is

The working repository of **SOHA** (Persian سها). The business started under the name **ENSA AI**, and the repo folder, `README.md` and `docs/` still use that name. It finds existing software products (SaaS, marketplaces, apps), works out where AI agents would add value, pitches the owner with a tailored proposal, and then builds the agent.

### How a proposal is built (the pattern to follow)

- **Code:** static HTML, CSS and JS, with no build step, no framework and no API keys. Each proposal has its own `assets/` folder and is a series of full-screen slides (`100svh` on desktop).
- **Typical sections:** opening hero, the ideas, one section per working demo, a connected-flow section, and a closing with a call to action. The contacts are `mailto:reza.tz780210@gmail.com` and `https://calendly.com/reza-tanakizadeh/soha`.
- **Honesty rules used on every proposal:**
  - Results are labelled "Prepared example".
  - Uploads stay in the browser, are never processed, and the page says so.
  - Nothing claims a feature is missing from the client's product or on its roadmap.
  - No undocumented client APIs are assumed.
  - A disclosure says the proposal is independent and not endorsed by the client.
  - Products, brands, people and prices are fictional.
- **Research first:** the client's brand colours, logo, typography and existing AI features. Don't pitch what they already have.
- **Docs per proposal** in `docs/proposals/`:
  - `<client>.md`: research, sections, honesty notes, how to edit, checks done
  - `<client>-production-architecture.md`: how it would really be built
  - for image-heavy proposals, `<client>-image-prompts.md` and `<client>-assets.md`
- **Turkish pages:**
  - Shopier's is generated from the English page by `python3 tools/proposals/shopier_tr.py`. Edit the English page, then run it. It fails loudly if a translated string no longer matches.
  - Biletino and Düğün have hand-maintained `tr/index.html` files with the same markup, so a change goes into both.
- **Social images:** render a 1200 × 717 composition with headless Chrome, then crop the top 1200 × 630 with ffmpeg. The Shopier composition page was a temporary file in `/tmp`; rebuild it if needed.

## 5. Shopier in detail (the latest work)

Page: <https://mertz1999.github.io/soha/proposals/shopier/>. It has seven slides with three demos: an **AI Product Studio**, an **AI Campaign Studio** (3 directions × 4 formats, editable text, PNG/SVG export) and an **AI Virtual Try-On**. Everything is photographic now.

**Files:**
- `assets/proposal.js`: all interactions, plus the photo list and scene compositing
- `assets/campaign.js`: campaign layout engine and exports
- `assets/art-*.js`: code-drawn illustrations, used only as fallbacks
- `assets/shopier.css`: styles
- `assets/photos/*.webp`: the photos

**How the product photos work.** The user generates images from prompts. To keep their count low, scenes are composited instead of generated:
- Each product (bag, earrings on a stand, serum) has one phone photo, `<product>-original`.
- `tools/proposals/cutout.swift` cuts the product out with Apple Vision and cleans the edges, giving `<product>-cutout`. Usage:

  ```bash
  swift tools/proposals/cutout.swift in.jpg out.png
  ```

  Then convert the result:

  ```bash
  cwebp -q 90 -alpha_q 100 -exact out.png -o site/proposals/shopier/assets/photos/<product>-cutout.webp
  ```

- `proposal.js` draws the cut-out on 8 shared empty backgrounds (`bg-<style>-<n>`) in a canvas. Placement and light per background are in `BG`, and product size is in `FIT`.
- It makes three versions of each scene: square, 16:9 for the 16:9 format, and `ad` for the editorial campaign layouts.
- A photo is used only if its base name is in the `PHOTOS` set in `proposal.js`. Anything missing falls back to the illustration.

**Try-on:** 2 models (Ada, Nil) × 2 garments (blazer, dress), with 4 results made in a try-on tool. In the delivered zip the two blazer results were swapped; they were renamed on import.

**Image prompts:** [shopier-image-prompts.md](docs/proposals/shopier-image-prompts.md) has 19 images in total (Part A: 11 for the products, Part B: 8 for the try-on). All are delivered.

## 6. How this user likes to work

- **Images:**
  - Don't generate images yourself. Write prompts, with the input images to attach, and the user generates them and sends a zip.
  - **Keep the number of images as small as possible.** The first Shopier list of 61 was rejected.
  - Design so one image is reused many times (cut-outs, shared backgrounds, compositing).
  - Always keep code-drawn illustrations as the fallback, so the page works before photos arrive.
- **Checking deliveries:**
  - Unpack zips into a new empty folder, such as `/tmp/<name>/`, and look at every image before using it.
  - Check that file names match their content. One delivery had two files swapped.
- **Internet images:** don't use them for demos with people or products. Licences and model releases are a problem, and they would make the "AI example" labels untrue. The try-on research datasets (VITON-HD, Dress Code) are non-commercial only.
- **Publishing:** "Publish now" or "deploy it" in the user's message is approval for that one push. Otherwise, ask.
- **Testing:** after any change to a page, test it at 1440 × 900 (every slide should be exactly one screen tall), at 1920 × 1080 and at 375 px on mobile. Check the console for errors and both languages, then report what was checked.
- **Communication:** the user writes quickly, with typos. Answer in plain English, briefly, and say clearly what is done, what isn't, and what's live.
